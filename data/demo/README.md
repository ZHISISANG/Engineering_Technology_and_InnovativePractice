# 演示数据（合成样本）

这些 CSV/JSON 是为演练和测试编造的，**不对应任何真实展会、企业或个人信息**。
人物姓名来自需求发现报告中的虚构角色；手机号、公司名、时间均为构造值。

## 数据规模

| 文件 | 内容 | 说明 |
| --- | --- | --- |
| `service_desk.csv` | 17 行 / 16 张工单 | 服务台导出；含 1 条重复编号（T-1004），用中文表头验证别名映射 |
| `file_index.csv` | 12 个版本 | 文件库导出；含过期、作废、未确认、替代链断链、两个“已确认”冲突 |
| `ledger.csv` | 16 行 | 业务台账；处理时长混用 min / 分钟 / hour，用于验证单位归一 |
| `handoff.csv` | 16 行 | 交接记录；含“已处理”空交接、版本漂移、未确认项归到接收方 |
| `manifest.json` | 1 份 | 授权范围仅 2026-S1；用于验证跨批次授权拦截 |

## 这份数据故意埋了哪些坑

1. **T-1002**：业务发生时间早于所有版本有效期 → 无当前版本。
2. **T-1003 / T-1014**：收费、参展资格 → 不可逆边界，草稿不得直接对外。
3. **T-1004**：重复编号 + 交接版本过期 → 重复行保留原行，版本漂移。
4. **T-1005**：V-1008 与 V-1011 都“已确认”且都覆盖当天 → 版本冲突，不猜。
5. **T-1006**：V-1009 指向不存在的 V-9998 → 版本链断。
6. **T-1007**：发生 10-14、接收 10-15，相差 33 小时 → 回填样本。
7. **T-1008**：批次 2026-S2 不在授权范围 → 拒绝处理。
8. **T-1009**：业务发生时间为空、接收时间有值 → 缺失 ≠ 未确认。
9. **T-1010**：台账写 `1.5 hour` → 归一为 90 分钟并留换算说明。
10. **T-1011**：存在 `最新版_展位说明_最终版.pdf`（V-1012，未确认、后到），
    但判定仍取有效期覆盖且已确认的 V-1002 —— 文件名不参与排序。
11. **T-1013**：交接只写“已处理” → 交接缺项，不能算完成。
12. **T-1015**：交接写的版本是 V-1005，实际当前版本 V-1002 → 版本漂移。

## 重新生成

不需要脚本：这些文件本身就是测试夹具，被 `tests/` 与 `examples/demo.py` 直接引用。
若改动数据，请同步更新 `tests/test_end_to_end.py` 中的计数断言。
