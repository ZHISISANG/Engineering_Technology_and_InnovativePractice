# 试点运行手册（4 周 / 2 人 / 每周 ≤4 小时）

本手册把工具放进真实流程的最小可行方式。它假设：**只读导出、只出草稿、单批次、人工确认**。
任何一步超出这个范围，先停下来重新评估，而不是加大自动化。

---

## 1. 边界（开始前必须逐条确认）

| 边界 | 具体要求 | 违反时 |
| --- | --- | --- |
| 数据 | 仅使用脱敏只读导出；不连生产库、不写回源系统 | 立即停止 |
| 批次 | 只覆盖 `2026-S1` 一个批次 | 拒绝运行 |
| 输出 | 只生成审核用草稿，不自动发给展商 | 立即停止 |
| 收费/资格 | 不自动作出任何收费、报价、资格决定 | 转人工，记录原因 |
| 权限 | 正式结论必须由授权人员确认；模型无审批权 | 确认无效 |
| 停止权 | 审核方与业务负责人可随时暂停 | 工具停止出草稿 |

对应配置在 `config/default.yaml` 的 `safety` 段，写错任何一项工具会拒绝启动。

## 2. 角色

| 角色 | 人（材料中的化名） | 在试点里做什么 | 工时 |
| --- | --- | --- | --- |
| 业务负责人 | 顾明岚 | 决定是否继续；确认收费/资格类草稿；可暂停 | 每周 0.5h |
| 一线服务专员 | 林亦舟 | 提供真实咨询样本；核对草稿是否可用 | 每周 ≤2h |
| 项目流程协调员 | 唐映秋 | 版本判定复核；责任清单维护 | 每周 ≤2h |
| 数字化工程师 | 秦芮 | 导出、字段映射、跑工具、修数据问题 | 每周 ≤1h |
| 审核与质量负责人 | 傅景 | 逐条确认/退回；抽查；可暂停 | 每周 ≤1.5h |
| 客户协同代表 | 叶书 | 三项指标对账；误报/漏报复盘 | 每周 ≤1h |

**总预算**：2 名业务骨干为主，合计每周不超过 4 小时；超出即暂停并重新评估（f03）。
这里的“2 名”指一线服务专员与项目流程协调员，其余角色按需参与，不摊派工时。

## 3. 运行前提（W0 完成，约 2 小时）

1. 从内部服务台、业务台账、文件库各导出一份 CSV，放入 `data/demo/export/` 同结构目录；
2. 在 `manifest.json` 写清 `authorized_scope.batches`、`purpose`、`expires_at`，并确认 `read_only: true`；
3. 个人字段（手机、邮箱、证件号）在导出时掩码；工具会再掩码一次；
4. 确认 `config/default.yaml` 的 `pilot.batch` 与导出批次一致；
5. 跑一次基线：

```bash
PYTHONPATH=src python -m expo_trace run \
  --export data/demo/export --run-dir runs/w0 --now "2026-10-20 10:00"
```

6. 打开 `runs/w0/output/report.md`，与协调员逐条过“人工队列”，确认责任人是否真实可承接。

> 如果这一步队列里出现“没有责任人”的条目，先补 `routing.owners`，不要开始计时。

## 4. 四周计划

### 第 1 周 · 版本判定对照（≤4h）

| 步骤 | 动作 | 产出 |
| --- | --- | --- |
| 1 | 从基线队列取全部问题单 + 随机 10 条正常单 | 对照清单 |
| 2 | 协调员对每条标注“当前 / 过期 / 未确认”，只依据有效期与确认状态 | 标注结果 |
| 3 | 与工具判定逐条比对，不一致的登记为误报/漏报 | `expo-trace feedback` 记录 |
| 4 | 审核方复核一轮，重点看“文件名像最新、实际已过期”的样本 | 复核记录 |

**通过条件**：能对每条问答说清“依据哪个版本、为什么不是另一个”，而不是“文件名叫最新”。
**不通过信号**：超过 1/3 的样本无法定位版本 → 暂停，先补版本台账。

### 第 2 周 · 交接编号与责任清单（≤4h）

| 步骤 | 动作 | 产出 |
| --- | --- | --- |
| 1 | 用脱敏导出做字段映射演练，确认四类脏数据判定 | 映射表 |
| 2 | 检查重复编号、空时间、版本断链、单位差异是否都在 `issues.csv` | 问题清单 |
| 3 | 给每条队列项补“接收人 + 责任清单 + 时限” | `queue.csv` |
| 4 | 抽查 5 条交接记录，确认没有“只写已处理”的情况 | 抽查记录 |

**通过条件**：每条转派都能回答“谁接、依据哪个版本、还有什么没确认”。
**不通过信号**：统一编号仍无法生成 → 记录为未解决依赖，不强行上线。

### 第 3 周 · 完成口径与周报（≤4h）

| 步骤 | 动作 | 产出 |
| --- | --- | --- |
| 1 | 两个团队各自报“完成”，用同一周三项指标对账 | 对账表 |
| 2 | 逐条复盘退回样本：为什么退、退了几次 | 返工记录 |
| 3 | 用 `expo-trace feedback` 登记本周误报/漏报/未确认 | 周报小节 |
| 4 | 检查“只用工时”的结论是否掩盖了返工 | 会议结论 |

**通过条件**：双方接受“工时 + 返工 + 确认完整率”三项并列，不再单独用处理速度排名。
**不通过信号**：任何一方坚持单一效率指标 → 该项留作未达成，写入结论。

### 第 4 周 · 验收与结论（≤4h）

| 步骤 | 动作 | 产出 |
| --- | --- | --- |
| 1 | 按 `sample` 计划抽取 80 条问答，逐条核对来源与人工复核记录 | 抽查表 |
| 2 | 跑 `audit verify`，导出审计链，确认“谁查过、用哪个版本、谁确认”可还原 | 审计凭证 |
| 3 | 对照 `docs/requirements-traceability.md` 的六条验收逐项打分 | 验收结论 |
| 4 | 给出三选一建议：继续 / 缩小范围 / 停止 | 决策记录 |

**通过条件**：六条需求中 P0 全部达到“业务侧通过”，且 80 条抽查无“来源缺失”。
**不通过信号**：出现一次“草稿被直接对外发送” → 停止，按事故复盘。

## 5. 每周固定动作（30 分钟周会）

1. 打开 `runs/<week>/output/report.md`，先看三项指标，再看队列；
2. 逐条过本周 `feedback.jsonl` 登记项，判定误报/漏报/未确认；
3. 确认下周是否继续，以及谁在何时段投入；
4. 会议结论写入周报“限制与下周”，不只写“进展顺利”。

周报由工具生成初稿，人补充判断；**工具不替人下结论**。

## 6. 暂停与恢复

暂停是审核方的权利，不是异常处理：

```bash
# 审核方或业务负责人发起
PYTHONPATH=src python -m expo_trace pause \
  --run-dir runs/w1 --actor 傅景 --reason "版本冲突样本过多，先核对台账"

# 暂停后任何 run 都会退出码 3，且不再生成草稿
# 恢复
PYTHONPATH=src python -m expo_trace resume --run-dir runs/w1 --actor 傅景
```

暂停期间：队列保留、草稿冻结、审计继续记录。恢复后不会自动补发暂停期间的草稿，需人工确认。

## 7. 数据与审计

| 数据 | 位置 | 保留 | 说明 |
| --- | --- | --- | --- |
| 原始导出 | `runs/<week>/input/` | 试点期 | 已掩码；只读 |
| 快照 | `runs/<week>/snapshots/last/` | 试点期 | 读取失败时兜底，带时间戳 |
| 审计链 | `runs/<week>/audit.jsonl` | 待定 | 追加写，可校验；保存期未核实 |
| 确认记录 | `runs/<week>/reviews.jsonl` | 待定 | 含确认项与草稿摘要 |
| 报告 | `runs/<week>/output/report.md` | 试点期 | 含三项指标与限制 |

- 只删除虚构的个人字段，不删业务字段、版本链与确认记录（f43）；
- 审计凭证的保存期限与导出格式尚未确认，试点结束前必须由审核方定；
- 不把 `runs/` 提交到公开仓库（`.gitignore` 已排除）。

## 8. 升级路径

| 情况 | 找谁 | 多久 |
| --- | --- | --- |
| 版本无法判定、冲突 | 项目流程协调员 → 审核与质量负责人 | 当班 |
| 收费/资格类草稿 | 业务负责人 + 审核与质量负责人 | 当班，不得先发 |
| 导出缺字段/读取失败 | 数字化工程师 | 4 小时 |
| 授权范围不清 | 审核与质量负责人 | 当天，未确认前不出草稿 |
| 疑似草稿外发 | 业务负责人（立即暂停） | 立即 |

## 9. 退出条件（满足任一即停止，不转正式）

- 无法保证只读导出，或出现写回源系统的需求；
- 收费/资格决定无法做到人工确认后才对外；
- 80 条抽查中“来源缺失”超过 5%；
- 连续两周无法在 4 小时内完成既定动作；
- 审核方或业务负责人任一方要求停止。

## 10. 命令速查

```bash
PYTHONPATH=src python -m expo_trace run --export <dir> --run-dir runs/w1 --now "2026-10-27 10:00"
PYTHONPATH=src python -m expo_trace status --run-dir runs/w1
PYTHONPATH=src python -m expo_trace review --run-dir runs/w1 --ticket T-1001 \
  --reviewer 傅景 --decision confirm --item 版本可定位 --item 来源可追溯 \
  --item 未确认项已列明 --item 用途与授权范围相符
PYTHONPATH=src python -m expo_trace feedback --run-dir runs/w1 --ticket T-1005 \
  --kind 误报 --reporter 傅景 --note "业务已确认该冲突，工具判定过严"
PYTHONPATH=src python -m expo_trace audit verify --run-dir runs/w1
PYTHONPATH=src python -m expo_trace report --run-dir runs/w1
```
