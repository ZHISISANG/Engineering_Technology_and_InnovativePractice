展商咨询工单的版本追溯

从「先答复、后补表」到「只出草稿、可复核」：5 张图说明现状断点、工具边界、版本判定、确认状态与审计链。

依据《展商咨询知识与服务转派》需求发现材料整理 · 访谈 36/36 覆盖 · 6 个角色 · 6 条待验证需求

绿：可出草稿 / 已定位 黄：进人工队列 / 需确认 红：不可逆边界 / 禁止对外 蓝：数据与判定步骤 灰：断点与证据编号

01现状链路：答复发生在登记之前

流程本身只有五步，断点出在“先解决、后补录”和“三套系统各记一段”。

咨询接收电话 / 邮件 / 群消息
问题分类时间、费用、展位、资格
版本检索服务台 / 台账 / 文件库
转派交接接收人 · 版本 · 未结项
回复审核对外口径
断点 1 · 时间是补的

先在群里答复，事后才补表格，回填时间晚于真实发生时间数小时到数天。 f13

断点 2 · 版本靠文件名判断

问答引用旧通知，时间或费用口径与现行版本不一致；展位调整后旧说明仍指原区域。 f10 / f11

断点 3 · 工单没有统一编号

三类工具各有一套记录，交接只能人工比对，版本断链后无法追溯。 f30

02工具边界：只读、只出草稿、失败进队列

工具不替人答复，也不替人审批；它只负责把“依据哪一版、谁确认、还缺什么”摆到桌面上。

  1. 只读导出

    4 张脱敏表 + 授权清单，单批次、只读、无写回接口。

    输入 service_desk / ledger / file_index / handoff 　产出 输入哈希

  2. 字段映射

    中文/英文表头别名匹配，原始行整行保留，个人字段先掩码。

    产出 tickets.jsonl（含 raw）

  3. 数据核对

    重复编号、空时间、单位差异、版本链、交接缺项、授权范围。

    产出 issues.jsonl + issues.csv

  4. 版本判定

    只按“有效期覆盖 + 确认状态 + 作废状态 + 替代链”，不看文件名与修改时间。

    产出 resolutions.json（含已排除版本与理由）

  5. 草稿组装 或 人工队列

    可定位 → 带来源、行号、版本的草稿；不可定位 → 原因 + 责任人 + 时限。

    产出 drafts/*.md、queue.csv

  6. 不可逆边界

    收费、报价、退款、参展资格：一律标记“禁止对外”，须业务负责人 + 审核方书面确认。

    产出 blocked 草稿 + 队列项

  7. 人工确认 / 周报

    四项确认齐全才算确认；工时、返工、确认完整率三项并列，不给单一效率结论。

    产出 reviews.jsonl、report.md、checklist.md

读取失败不编造、不静默重试：使用上次成功快照续跑，报告标注快照时间并提示人工核查（f35）。

03版本判定：凭什么说这一版是“当前版本”

排序键只有四项：是否确认、是否作废、生效起始、确认时间；文件名即使叫“最新版”也不参与。

工单：批次 · 类别 · 业务发生时间
业务发生时间可判定？（缺失、未确认、非法都不算可判定）
否 → 人工队列

KEY_FIELD_MISSING / KEY_FIELD_UNCONFIRMED

是：看有效期
有效期内有覆盖该时点的版本？
否 → 人工队列

NO_CURRENT_VERSION，附最近过期版本与作废原因

是：看确认状态
存在已确认版本？替代链完整？只有一个胜出？
否 → 人工队列

KEY_FIELD_UNCONFIRMED / VERSION_CHAIN_BREAK / VERSION_CONFLICT

是 → current + version_id

草稿可引用；仍保留“未确认 · 不可对外”标识

作废记录不删除，保留作废原因；后到的未确认版本不得覆盖已确认版本（f24 / f34）。

04确认状态：草稿不是答复

每条工单最终只会落在四种状态之一，没有“默认通过”。

状态进入条件离开条件
草稿待确认版本可定位，无阻断问题审核人 confirm（四项齐全）或 return（须写原因）
人工队列版本不可定位 / 冲突 / 链断 / 缺字段 / 授权不清 / 交接缺项补齐后重跑；或复核后转边界阻塞
边界阻塞收费、报价、退款、参展资格业务负责人 + 审核方书面确认，仍不得自动对外
试点暂停审核方行使停止权（f04）审核方恢复后重跑

确认必须覆盖四项：版本可定位、来源可追溯、未确认项已列明、用途与授权范围相符。确认记录写入哈希链，事后可查“谁在什么时候确认了哪几项”。

05审计链：改一行，后面全对不上

审计不是最后写一段总结，而是每次动作追加一条带前序哈希的记录。

run_started谁、何时、用哪份配置与导出
→
review_submitted谁确认、哪几项、什么建议
→
query / show谁查过哪张工单
→
hash + prevsha256 链接，断点可定位

校验命令：expo-trace audit verify。输出会指出第几条开始对不上，而不是只给“校验失败”。
