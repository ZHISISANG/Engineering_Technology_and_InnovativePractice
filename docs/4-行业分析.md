# 会展行业数字化与服务转派 · 行业分析

> 版本 v1.0 ｜ 2026-11-06 ｜ 与 `行业分析.docx` 同源 ｜ 案例：展商咨询知识与服务转派

> 说明：本文不含第三方市场统计数字；企业业务方向引用公开来源，人物与业务数据为演练样本。

## 1. 行业边界与角色

| 角色 | 承担的事 | 与本项目的关系 |
| --- | --- | --- |
| 主办 / 组展方 | 招展、排期、现场运营、展商服务 | 需求方：本案例的委托方 |
| 场馆 / 服务商 | 搭建、物流、安保、餐饮住宿代订 | 规则来源之一（住宿、物流口径） |
| 展商 | 参展报名、证件办理、现场咨询 | 服务对象：问的是时间、费用、资格口径 |
| 内部一线与审核 | 受理、转派、回复审核 | 工具使用者：咨询员与审核方 |

会展服务的链条长、参与方多，同一件事的“标准”常由多方共同定义，这是口径冲突的根源。

## 2. 行业数字化趋势

| 趋势 | 表现 | 对本项目的约束 |
| --- | --- | --- |
| 服务线上化 | 展商咨询从电话/现场转向在线工单 | 需要可追溯的工单与统一编号 |
| 知识与规则平台化 | 通知、规则、FAQ 集中管理 | 版本治理比“有没有文档”更关键 |
| 客服智能化 | RAG 问答、智能转派 | 必须有引用、可拒答、不越过不可逆边界 |
| 合规与留痕 | 个人信息保护、审计可回查 | 只读导出、脱敏、哈希链留痕 |

行业整体在从“流程上网”走向“规则可执行”，但多数团队卡在版本与责任边界，而不是模型能力。

## 3. 共性痛点（本案例已复现）

| 痛点 | 现场证据 | 造成的成本 |
| --- | --- | --- |
| 版本口径不一致 | 旧通知、旧展位说明仍在流通（f10、f11） | 返工、现场折返、重复核对 |
| 时间口径失真 | 先群消息后补填，回填时间≠发生时间（f13） | 工时被低估、基线不可信 |
| 交接断链 | 只写“已处理”，无版本与未结项（f23、f30） | 责任无法定位、追溯靠人工 |
| 完成口径不一 | 客服要少转派、业务要求专人确认（f50） | 跨团队无法对齐验收 |

痛点集中在“对不上”而不是“算得慢”，因此优先级应给判定与留痕，而不是扩大自动化。

## 4. 技术与合规约束

| 约束 | 具体含义 | 设计回应 |
| --- | --- | --- |
| 模型不确定性 | 同一问题可能给出不同表述 | 只做草稿；引用必须来自检索；无依据拒答 |
| 不可逆动作 | 收费、报价、资格、退款一旦发出无法撤回 | 系统不提供发送通道，只到草稿 |
| 个人信息 | 展商联系人、证件、票据影像 | 只读导出 + 脱敏 + 不落原图 |
| 审计要求 | 事后要能解释“依据哪一版、谁确认” | 版本号随回答落库；审计哈希链 |

合规不是文档附录，而是接口与数据结构的约束：没有发送接口、没有写回接口，违规才不可能发生。

## 5. 可借鉴的实践与差距

| 实践 | 成熟做法 | 本项目的差距与选择 |
| --- | --- | --- |
| 知识检索 | RAG + 版本过滤 + 引用 | 已有 (v3 原型 + 阶段 2)，缺真实语料与评测集 |
| 人工复核 | 四眼原则、职责分离 | 已落地：草稿→人工复核→审核方确认 |
| 质量度量 | 准确率 + 返工 + 完整性 | 已落地三项并列指标，缺真实样本量 |
| 上线运维 | 灰度、回滚、巡检 | 本机试点；公网部署与监控待补 |

差距不在“有没有 AI”，而在数据可得性与运维成熟度；因此先做只读试点，再谈扩大自动化。

## 6. 对本项目的启示

- 先解决“版本与责任能不能对上”，再谈效率提升；顺序反了会把旧口径的错误放大。
- 工具边界要写进接口：没有发送、没有写回、没有自动通过；这比提示词约束可靠。
- 度量必须三项并列（工时、返工、确认完整率），单一效率指标会掩盖质量下降。
- 试点只覆盖一个批次，用 80 条抽查验证来源可追溯，再评估扩围。
